# Development workflow

The authoritative process is "Development process" in `AGENTS.md`. This skill is the runnable checklist (`scripts/ticket.mjs` + `scripts/lib/*.mjs`). Keep this file identical in `.agents/skills/` and `.claude/skills/`.

1. **Plan.** Investigate read-only (use `node scripts/ticket.mjs map [<filter>]` for a fast zero-dep symbol outline). Propose Summary, Acceptance criteria, Steps, Risks and Out of scope. Wait for approval and quote it under Notes. For new projects or multi-PR initiatives, optionally scaffold an architecture blueprint first with `node scripts/ticket.mjs blueprint "<Topic>" [--version <ver>]` (or list/inspect slice rollup with `node scripts/ticket.mjs blueprint [list|status]`).
2. **Plan doc.** Copy `docs/plans/_template.plan.md` to `docs/plans/FT-Plan-<Topic>-<YYYY-MM>.plan.md` or scaffold with `node scripts/ticket.mjs new "<Topic>" [--type Feature|Bug|Refactor|Spike] [--appetite S|M|L] [--timebox <duration>] [--version <ver>] [--impact none|patch|minor|major] [--blueprint <path>] [--depends-on "<list>"] [--context "<findings>"] [--branch]`. The title reads `<Plan|Debug|Ask> - <Type>: <Title>` (for example `Plan - Feature: Smart Shortcut Suggestions`; use `--type Spike` for time-boxed experiments with `## Hypothesis` and `## Findings & Recommendation`); optionally set `priority`, `state`, `due`, `appetite` (`S|M|L`), `timebox`, `version`, `impact` (`none|patch|minor|major`), `blueprint`, and `dependsOn` in the frontmatter (use `node scripts/ticket.mjs ready [--blueprint <path>] [--claim --agent <you>] [--release]` to query or claim unblocked plans). Fill `## Context` with compacted file:line findings and resolve `## Open questions` before `start`. Write observable `AC#` criteria and map steps with `(AC#)`. Bigger than one PR? Split it into one plan per PR.
3. **Ticket.** Run `node scripts/ticket.mjs lint <plan>` (0 tokens) to catch placeholders, unresolved open questions, or uncovered `AC#` IDs, then `node scripts/ticket.mjs create <plan> --agent <your client: Claude, Codex, Gemini or Other>`. In Notion mode, new Tasks start To Do, stamp Development and a stable Dev Ticket Key (plus `Target Version` when `version` is set), and have no Focus Slot or scheduling Date; creation reads the key first and restores an existing canonical URL without changing that Task. In local mode (`tracker: "local"`), it stamps `local://<key>`. Preserve `devTicketKey` when renaming a plan; do not create the same plan concurrently.
4. **Start.** Create a branch, commit the plan on it, then `node scripts/ticket.mjs start [<plan>]`.
5. **Implement.** Re-read the plan before each step. Cold start / resume: run `node scripts/ticket.mjs prime [--verify]` for a compact session primer (and optional baseline health check), `node scripts/ticket.mjs resume [--verify]` for handoff state, or `node scripts/ticket.mjs overview` for multi-repo status. When `agentic.models` is configured, `step --role planner|builder|fixer|reviewer` and `prime` display the target model per role (in Antigravity, delegate to `swarm` workers pinned to each role's configured `model`; other clients may customize or omit `agentic.models`). Tick each checkbox as soon as it is done with zero tokens: `node scripts/ticket.mjs tick <#|query> [--verified <evidence> | --verify-cmd "<cmd>" | --red "<cmd>"] [--evidence-type test|cmd|manual|inspect]`. Ticked acceptance criteria end with concise `verified:` or `verified(test|cmd|manual|inspect): <how and result>` evidence (1 line, no raw terminal dumps); `--red` stamps failing reproduction without ticking. Never delete a checkbox; mark it `deferred: <reason>` instead via `node scripts/ticket.mjs defer <#|query> --reason <why>`. Record architectural choices in `docs/decisions/` with `node scripts/ticket.mjs adr "<Title>"` and capture lessons in `docs/lessons.md` with `node scripts/ticket.mjs lesson "<takeaway>" [--tags <a,b>]` (also auto-captured on `Bug`/`Debug` close-out and `review: block` -> `pass`). Search past decisions, blueprints, workflow docs, plans, and lessons with `node scripts/ticket.mjs recall "<query>" [--lessons] [--fleet]`. View local workflow metrics with `node scripts/ticket.mjs stats [--fleet] [--days <N>] [--all-overlaps] [--json]`. Manage release trains in versioned repos with `node scripts/ticket.mjs release [status|notes|closeout|init] [<version>]`. Archive completed or merged plans with `node scripts/ticket.mjs archive [--all|--merged] [--fleet] [--dry-run]`. Manage isolated worktrees with `node scripts/ticket.mjs wt [list|new|prune] [--fleet]`. Diagnose repo health with `node scripts/ticket.mjs doctor [--fleet]` and backfill downstream invariants with `node scripts/sync.mjs [--all-known] [--ensure-invariants]`. Manage pre-push / runtime agent hooks with `node scripts/ticket.mjs hook [install|uninstall|status] [--agent-hooks]`. When adding new commands, flags, or configuration options, always update `README.md`.
6. **Before you stop.** `node scripts/ticket.mjs handoff --agent <you> --done "<done>" --next "<step>" [--open "<questions>"]` (or `log`), then commit the plan.
7. **Review (mandatory independent review).** Run `node scripts/ticket.mjs pack [<plan>] [--test]` (one command, 0 LLM tokens, embeds test results with `--test`) to inspect the plan criteria, hygiene status, and filtered diff (or `node scripts/ticket.mjs review --prompt` for a structured reviewer brief). Every PR-sized plan **MUST** be reviewed by an independent sub-agent, fresh session, or second model checking plan fidelity, regressions, and verification honesty (`requireReview: true`, `allowSelfReview: false` by default; in Antigravity, spawn a `swarm` reviewer worker on `agentic.models.reviewer` such as `gemini-4-neon-low`). Stamp the result with `node scripts/ticket.mjs review [<plan>] --agent <reviewer-client> --reviewer-id <subagent-id> [--model <model-id>] --verdict <pass|warn|block> --summary "<concise findings>"` (`--reviewer-id` may be omitted only when `--agent` differs from `plan.meta.agent`).
8. **Close out.** `node scripts/ticket.mjs check [<plan>]` must pass. Tell the user about any deferred item.
9. **Ship.** Open the PR and ship in one command: `node scripts/ticket.mjs pr [--verify] [--auto] [--draft] [--retro "<takeaway>"]` (or open the PR manually with the template filled in, then `node scripts/ticket.mjs ship [<plan>] --pr <url> [--retro "<takeaway>"]`). Merge via `node scripts/ticket.mjs merge [<plan>]` to close the Task locally without Actions minutes (or let `ticket-done.yml` close it on merge); never mark a Notion Task Done before the PR merges.

Continuing someone else's work: find the plan with `status: in-progress`, read it fully including the Progress log, and resume at the first unticked step.

If any `ticket.mjs` command fails, report the error and stop at that step.
